# RAG的基本概念

RAG=Retrieval(检索)+Augmented(增强)+Generation(生成)
RAG即==检索增强生成==,为大模型提供了从某些数据源检索到的信息,并基于此修正生成的答案,RAG基本是search+LLM提示,可以通过大模型回答查询,并将搜索到的信息作为大模型的的上下文

(模型再生成答案之前,系统会从知识库中检索信息,再把收集到的信息结合问题丢给大模型,大模型再基于此生成答案)
# 搭建RAG的基本流程
![[搭建RAG的流程图.png]]
## 索引过程(创建本地知识库)
1. 数据接入:**收集pdf,html, word**等文档
2. 文档解析:**提取文本内容**
3. 进行文档分块:将长文档分成n个小的片段
4. 向量化(构建向量数据库):将文本转换为数学向量
5. 存储:将向量存入专门的数据库
## 检索过程(从本地知识库检索问题)
1. 加载并创建检索器
2. 利用检索器进行相似度检索,检索K个相似度最高的文本块
3. 将检索出来的内容+用户问题传递给大模型


# 为什么需要RAG:
1. **降低大模型的幻觉**:大模型的文本输出是基于概率生成的
2. **时效性提升**:大模型的回答是基于训练时的数据,对之后的数据缺失,时效性较差,使用RAG增强可以检索当前的信息,提高大模型输出的时效性
3. **降低模型训练成本**:减少模型微调成本
4. **数据安全问题**:如果单纯通过模型训练让模型知道公司的规章制度,需要将公司数据丢个模型训练这样会造成数据泄露,如果开放RAG设置管理员才能启用专属达到知识库可以避免数据泄露
5. **提升开发与调试效率
