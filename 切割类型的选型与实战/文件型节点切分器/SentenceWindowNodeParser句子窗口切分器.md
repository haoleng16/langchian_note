# 概述
SentenceWindowNodeParser的工作流程核心在于检索单元和上下文窗口的分离:
1. **精细索引**：在索引构建阶段，它会将文档拆分成**单个句子**作为基础节点（Node）。这种细粒度拆分有助于**向量模型更好地表征句子语义**，从而在检索时能更精准地找到相关句子。

2. **窗口上下文**[[SentenceWindowNodeParser句子窗口切分器#关于窗口上下文的理解]]：每个句子节点都会在元数据（metadata）中存储其**周围句子**构成的窗口文本。检索时，系统首先找到最相关的句子节点，然后**将其替换为对应的上下文窗口**，再将这个更大的文本块传递给LLM生成答案。

## 关于窗口上下文的理解

在 RAG（检索增强生成）中，我们在**切分文档（Chunking）**时面临一个两难的选择：
- **切得很细（比如按句子切）：**
    
    - **优点**：检索非常精准。用户的提问和这一句话的匹配度极高
    - **缺点**：给 LLM（大模型）看的时候，因为只有孤零零的一句话，**缺乏前因后果**，AI 很难回答得全面，甚至会因为信息不足而胡说八道。
        
- **切得很粗（比如按 500 字切）：**
    - **优点**：内容丰富，包含上下文。
    - **缺点**：检索变得模糊，很多不相关的信息混在一起，导致检索命中率下降（原本那句关键的话被淹没在废话里了）。

**“窗口上下文”就是为了兼得二者的==优点==：**

- 搜索时：只用**最精准的一句话**去匹配。
- 回答时：自动把这句话**周围的上下文**（比如前后各 3 句）“偷梁换柱”拿出来给 AI。


# 总结说明
核心原理:将文档句子拆分并建立索引,检索时返回匹配的句子以及周围的句子(滑动窗口)
主要优势:检索用小粒子==提升精度==,并且能给LLM提供更完整的窗口文本
**参数说明**
```
node_parser = SentenceWindowNodeParser(
    sentence_splitter=split_chinese_sentences,  # 自定义中文拆句器
    window_size=1,                              # 左右各1句作为window
    window_metadata_key="window",               # metadata 中存储窗口的 key
    original_text_metadata_key="original_text", # 可选：保存原始文本
    include_metadata=True,                      # 是否包含 metadata
    include_prev_next_rel=True,                 # 是否包含上一句与下一句的关系
)
```

| 参数                                           | 说明                                                                                                                                            |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `sentence_splitter=split_chinese_sentences`  | 根据中文的标点符号将文本进行一句一句的拆分                                                                                                                         |
| `window_size=1`                              | 窗口的大小,**Window Size = 1**：意味着往**前**看 1 句，往**后**看 1 句,- **存储的窗口内容**：[句1 + **句2** + 句3]                                                         |
| `window_metadata_key="window"`               | 切分后的 Node 对象里有一个 metadata 字典。这个参数决定了你用什么名字去存那个扩充后的长文本`node.text = "句2" # 实际做向量检索的是这个短句子 node.metadata["window"] = "句1。句2。句3。" # 给大模型看的是这个长句子` |
| `original_text_metadata_key="original_text"` | 虽然 node.text 本身就是原始文本，但为了保险或后续处理方便，这里会在 metadata 里再存一份当前句子的文本                                                                                 |
| `include_metadata=True`                      | 这是一个总开关。必须设为 True，否则上面的 window 和 original_text 都不会被保存进节点里。如果设为 False，这个切分器就退化成普通的句子切分器了。                                                      |
| `include_prev_next_rel=True`                 | 让 Node 对象知道它的“上一句”是谁，“下一句”是谁。                                                                                                                 |
## 窗口大小的选择

  - 太小：可能无法提供足够的上下文，影响LLM的理解。
  - 太大：会增加传递给LLM的token数量，可能导致**成本上升和处理延迟**，甚至可能触及模型上下文长度限制。
  - 通常建议从3开始尝试，并根据效果调整。
